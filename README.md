# Рекомендация вин

Приложение использует готовый пайплайн, обучение внутри приложения отсутствует.
Признаки CSV должны быть в исходных единицах, как в test.csv.

## Локальный запуск

Проверенный интерпретатор: Python 3.12.13.
Из папки wine_app:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run app.py
```

Пути строятся относительно app.py, поэтому запуск возможен из другой директории:
`streamlit run /полный/путь/wine_app/app.py`.

Четыре вкладки: одно вино, модельные метрики, пакетный прогноз и коэффициенты.
Общий порог из боковой панели применяется ко всем решениям. Начальное значение
сохраняется из config.json без округления. Precision при изменении порога не обязана
меняться монотонно. Значения коэффициентов не доказывают причинности.

## Данные и выбор

Сохранено исходное стратифицированное разбиение: 4547 train, 1950 test, seed 42.
Полные повторы сохранены для соответствия шаблону; 537 тестовых строк имеют аналог
в train. Это ограничивает переносимость оценки на новые независимые образцы.
Модель выбрана по F1 на validation (25% внешнего train). Для baseline проверены все
различные пороговые решения, для balanced и ресемплинга сравнивался порог 0.5.
Test не участвовал в выборе. Модель затем обучена на полном внешнем train.
Название, точный порог и фактические тестовые метрики находятся в config.json.

## Кэширование

`st.cache_resource` хранит общий объект модели между перезапусками и сессиями.
`st.cache_data` возвращает копии таблиц и массивов: отдельно кэшируются test.csv и
вероятности класса 1. Порог не входит в ключ вероятностей, поэтому движение слайдера
не вызывает повторный predict_proba на test. Для исключённого из хеширования `_model`
передаётся отдельная сигнатура файла: mtime_ns и размер. При замене файла ключи модели
и вероятностей меняются. Аналогичная сигнатура используется для test.csv.
Обычный joblib.load без декоратора заново читает и создаёт модель при каждом rerun.

## Пакетный ввод

CSV: UTF-8, разделитель запятая, заголовки признаков из config.json.
Порядок столбцов произволен, дополнительные игнорируются. Пустые файлы, нехватка
столбцов, нечисловые значения, NaN и infinity отклоняются до прогнозирования.
is_red: 0 = белое, 1 = красное. Результат содержит probability_good и prediction;
его можно скачать кнопкой в приложении.

## Воспроизведение экспериментов

В родительской папке находятся HW3_MMDA_solved.ipynb, requirements-hw3.txt,
test_metrics.csv и validation_metrics.csv. Установите зависимости ноутбука
и выполните Restart & Run All из папки hw_3. Если локального Data/wine_quality.csv нет, ноутбук читает ту же таблицу из фиксированной версии репозитория курса.
`verify_hw3.py` проверяет контракты собственной регрессии, обработку CSV,
вкладки, крайние пороги и отсутствие повторного тестового predict_proba.

## Фактическая проверка

При локальном запуске сервер отвечал на проверку доступности. NotebookClient выполнил
20 кодовых ячеек в новом ядре без ошибок. Отдельный процесс загрузил joblib,
вероятности совпали с ноутбуком с rtol=atol=1e-12.
Проверки verify_hw3.py прошли: исходный градиент (ошибка 1.44e-10), контракт LogReg,
корректный и некорректный CSV, результат для скачивания, четыре вкладки AppTest,
точный порог по умолчанию и границы 0/1. Счётчик тестового predict_proba остался 1
после трёх смен порога; новый ключ сигнатуры модели вызвал пересчёт.

Финальная модель: StandardScaler -> LogisticRegression без весов классов.
Порог: 0.2688887270064362. Test: accuracy 0.78974, precision 0.47389,
recall 0.63969, F1 0.54444, ROC-AUC 0.81354, AP 0.51210.
Validation F1 выбранного решения: 0.54545.
